Ejemplo: DPU INT8/16 registrada

El top INT8_16_DPU_perf_top conserva el wrapper del repositorio. En este ejemplo se mide INT8/16; el programa permite elegir las once variantes DPU y cambiar de tecnología mediante el Liberty seleccionado.

45 nm incorporada el 18 de octubre de 2026. Se utiliza el Liberty NLDM typical de texto, a 1,10 V y 25 °C. Las vistas individuales conservan la documentación de su generación anterior; el estado actualizado y los resultados están en Verificación del ejemplo.

¿El programa actual sirve para cualquier DPU o TCU?

Las once DPU registradas ya están integradas. Los grafos individuales conservan la propuesta anterior basada en INT8. El estado actual y los perfiles se detallan en DPU y formatos integrados. La ampliación a octets y TCU sigue pendiente.

  • Para TCU: registrar sus tops, interfaces, parámetros y modos soportados.
  • Adaptar referencias y testbenches a secuencias HMMA, arrays y control.
  • Reemplazar el criterio universal de 96 FF y la prohibición de latches por controles propios de cada perfil.
  • Adaptar compilación, almacenamiento y recursos a la jerarquía TCU existente.

Una TCU dinámica se valida en sus distintos modos, conservando todo su hardware. Cambiar el modo ejecutado no cambia el área de esa TCU.

Quién elige y quién ejecuta

Elección y solicitud

  • React consulta GET /api/v1/catalog.
  • El usuario elige una de las once DPU e IHP130, Nangate45 o Nangate15.
  • Envía design_id y technology_id a POST /api/v1/experiments.
  • La API valida, guarda y encola; responde HTTP 202 con un ID.

Procesamiento y consulta

  • Un worker ejecuta el adaptador EDA mediante asyncio.to_thread.
  • GHDL, Yosys e Icarus son procesos temporales dentro del contenedor.
  • SQLite guarda los estados; /app/data/runs/<id> guarda artefactos.
  • React consulta el progreso, compara resultados y descarga CSV/ZIP.

En el grafo de arquitectura, las líneas discontinuas indican uso o implementación de contratos. ExperimentRepository y SynthesisGateway son interfaces de Python, no servicios adicionales.

Reinicio: una evaluación queued/running que quedó inconclusa se marca interrupted al arrancar el servicio. La cola de memoria no se reanuda automáticamente.

Construir la imagen no es ejecutar una evaluación

Estas etapas pertenecen al Dockerfile. Cada evaluación posterior comienza directamente con sus fuentes, biblioteca y manifiesto.

1 · Frontend

Node 22 + Vite compilan React. Se transfieren los archivos estáticos a la imagen final.

2 · Herramientas EDA

Se descarga OSS CAD Suite 2026-09-04 y se verifica su SHA-256.

3 · Runtime

Python 3.12 / Debian Trixie, build-essential y zlib1g-dev. La imagen verifica enlace nativo y GHDL como usuario sin root.

El contenedor final tiene un servidor FastAPI/Uvicorn. SQLite está embebido; no se necesita PostgreSQL ni un servidor Vite en producción.

Los comandos, en orden

Son los comandos y scripts del adaptador actual. Esta página los documenta; abrir los diagramas no ejecuta las herramientas de síntesis. Cada evaluación usa su propio directorio de trabajo.

1. Análisis VHDL

Se analizan dependencias en int8_16_lib y el wrapper en work.

ghdl -a --std=08 -fsynopsys -fexplicit --work=int8_16_lib \
  INT8_Mult.vhd INT8_Adder.vhd INT8_DPU.vhd

ghdl -a --std=08 -fsynopsys -fexplicit INT8_16_DPU_perf_top.vhd
2. Validación del RTL

Python genera vectors.txt: 256 casos firmados y resultado módulo 2¹⁶.

ghdl -a --std=08 -fsynopsys -fexplicit validation_tb.vhd
ghdl -e --std=08 -fsynopsys -fexplicit area_validation_tb
ghdl -r --std=08 -fsynopsys -fexplicit area_validation_tb \
  --assert-level=error --ieee-asserts=disable-at-0
3. Conversión a Verilog

ProcessRunner guarda stdout en design.v. Aún no hay celdas ASIC mapeadas.

ghdl --synth --std=08 -fsynopsys -fexplicit \
  --out=verilog INT8_16_DPU_perf_top > design.v
4. Síntesis y mapeo tecnológico

El adaptador ejecuta yosys -s synth.ys. Este es el contenido del script.

read_liberty -lib cells.lib
read_verilog design.v
hierarchy -check -top INT8_16_DPU_perf_top
synth -top INT8_16_DPU_perf_top -flatten -noabc
dfflibmap -liberty cells.lib
abc -liberty cells.lib
delete t:$scopeinfo
clean
check -assert
write_json mapped.json
write_verilog -noattr mapped.v
tee -o stat.json stat -liberty cells.lib -json
5. Modelos funcionales de las celdas

Yosys ejecuta simulation_cells.ys para generar cells_sim.v.

read_liberty -ignore_miss_func -ignore_miss_dir \
  -ignore_miss_data_latch cells.lib
write_verilog -noattr cells_sim.v
6. Validación de la netlist

Se vuelven a comprobar los mismos 256 vectores. No es simulación de timing.

iverilog -g2012 -s area_validation_tb -o mapped_sim \
  validation_tb.v mapped.v cells_sim.v
vvp mapped_sim
Las comprobaciones deben aprobarse antes de publicar el resultado. Un error de herramienta, operador sin mapear o diferencia funcional se guarda como fallo, no como área cero.

Cómo se obtiene el área

Área total = Σ cantidad de celdas × área de cada celda

Se cruzan mapped.json y cells.lib, se clasifican funciones combinacionales y estado, y se comprueba la suma con stat -liberty. Las unidades siguen la convención documentada de cada biblioteca.

Controles actuales

  • RTL y netlist: 256 vectores firmados, incluidos casos de overflow.
  • 96 FF; sin latches ni macros inesperados.
  • Todos los tipos de celdas deben tener área y estar mapeados.

Alcance del piloto

  • Incluye lógica y registros del wrapper.
  • Excluye routing, pads, floorplan y clock tree.
  • No impone frecuencia ni ejecuta STA o equivalencia formal.
